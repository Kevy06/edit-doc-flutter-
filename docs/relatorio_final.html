Relatório Técnico e Reflexivo

Nexo Docs — DocEditor MVVM · Etapa final

1. Alterações realizadas no código

A versão inicial migrada para MVVM mantinha os documentos somente em memória. Ampliei o modelo Documento com um identificador e os métodos toMap() e fromMap(). Depois criei DocumentoStorageService, que converte a lista para JSON com jsonEncode, grava a string em shared_preferences e reconstrói os objetos com jsonDecode na inicialização.

O DocumentosViewModel carrega os dados de forma assíncrona e concentra as operações de criar, selecionar, salvar e excluir. A biblioteca abre EditorView para alterar cada documento. As Views chamam métodos do ViewModel e não acessam diretamente o serviço de armazenamento.

Implementei PreferencesService para salvar a escolha de tema e os dados de identificação da sessão. O TemaViewModel controla a alternância entre tema claro e escuro. O AuthViewModel integra as telas de login e cadastro ao serviço local de demonstração, restaura a sessão ao abrir o app e remove a sessão ao sair.

2. Mudanças estruturais

Antes, o estado dos documentos existia somente enquanto o processo estava aberto. Agora, o fluxo é View → ViewModel → Service → shared_preferences; na leitura, o caminho é percorrido no sentido inverso. O ViewModel notifica as Views com notifyListeners() e ListenableBuilder.

Cada documento é convertido em um mapa com id e conteudo. jsonEncode() transforma a lista de mapas em uma string armazenável. No carregamento, jsonDecode() recria a lista e Documento.fromMap() converte cada mapa para o modelo. As chamadas de leitura e escrita usam async/await, e o app aguarda a restauração inicial antes de escolher a rota e o tema.

As rotas /, /cadastro, /home e /editor conectam as quatro telas. O main.dart instancia os ViewModels compartilhados e injeta suas dependências nas Views. O tema e a sessão são restaurados antes da exibição do fluxo principal. O logout limpa a identificação da sessão, sem remover documentos nem a preferência de tema.

3. Dificuldades encontradas e soluções

O primeiro teste de interface verificava o login antes da conclusão da leitura assíncrona de preferências. Ajustei o teste para inicializar o mock de shared_preferences e aguardar a inicialização com pumpAndSettle(). Depois disso, os testes de interface e persistência passaram.

O comando flutter do ambiente local ficou aguardando no mecanismo de inicialização do SDK, sem apresentar saída. Executei o Flutter Tool diretamente pelo snapshot do SDK; assim foi possível concluir a análise estática, os testes e a compilação Web. A aplicação foi compilada com o caminho base /edit-doc-flutter-/, necessário para este repositório no GitHub Pages.

Para o APK, reduzi a memória do Gradle conforme o roteiro. A tentativa parou antes de iniciar o Gradle porque não há Android SDK instalado neste Windows (No Android SDK found). Por isso, não foi possível gerar nem validar o instalador Android neste ambiente.

A versão Web compilada foi enviada para a branch gh-pages sem reescrever o histórico. A consulta pública da configuração do Pages retornou 404, então a hospedagem ainda não está ativa nas configurações do repositório. É necessário escolher Settings → Pages → Deploy from a branch → gh-pages → /(root) para liberar o endereço público.

Resultados e limites observados

  • flutter analyze --no-pub: sem problemas encontrados.
  • flutter test --no-pub: quatro testes aprovados, cobrindo tela inicial, persistência e CRUD, tema e restauração da sessão.
  • flutter build web --release --base-href "/edit-doc-flutter-/": compilação concluída em build/web.
  • APK Android: pendente, pois este computador não tem Android SDK configurado.
  • GitHub Pages: arquivos enviados para gh-pages; ativação do Pages ainda pendente nas configurações do repositório.

O cadastro é local e em memória, pois o roteiro não define um backend de usuários. A conta prof@email.com / 123456 é apenas para demonstração. A sessão persistida contém nome e e-mail; a senha não é salva. Contas cadastradas desaparecem ao reiniciar, portanto essa solução não deve ser usada com credenciais reais.
